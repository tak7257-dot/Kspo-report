# 덜붐빌때 v3 설계: "차를 가져갈까?"부터 정해 주는 공연 날 주차 비서

작성 2026-11-23 · 대상: 관람객용 웹 (`web/app/index.html`) 전면 개편 · 제출 마감 2026-12-01 18:00 (목표 11/30)

## 1. 의도와 이유

- 공모전: 2026 한국체육산업개발 공공데이터 활용 경진대회. 심사 기준은 활용 우수성, 구체성, 독창성, 실현가능성, 공익성.
- 지금 웹은 "공연장 3D + 도착 시각" 화면 3장이다. 상용 서비스(좌석 시야 앱, 지도 앱)의 하위호환처럼 보여 독창성이 약하고,
  지하철 관객처럼 데이터가 답하지 못하는 질문에 허점이 있다.
- 한국체육산업개발 데이터는 본질적으로 **주차 데이터**다. 그래서 앱의 첫 질문을 "어떻게 갈까?"가 아니라
  **"이날 차를 가져가도 될까?"**로 둔다. 데이터가 답할 수 있는 질문만 묻기 때문에 허점이 구조적으로 생기지 않는다.
- 공익성: 붐비는 날 차를 덜 가져오게 하고(교통 분산), 차로 온 사람은 도착·출차 시각을 나누게 한다.

## 2. 사용자와 쓰는 순간

| | 처음 오는 관객 | 자주 오는 관객 |
|---|---|---|
| 모르는 것 | 차를 가져가도 되는지, 몇 시에 와야 하는지, 공연장이 어떤지 | 오늘이 평소와 다른지, 언제 차를 빼야 하는지 |
| 여는 때 | 공연 며칠 전, 한 번 꼼꼼히 | 공연 당일, 특히 **공연이 끝나 차를 뺄 때** |

사용자가 지목한 핵심 순간: **차를 빼거나 나갈 시간을 고민할 때.**

## 3. 목표 / 하지 않을 것 / 실패로 볼 것

목표
- 첫 화면 한 장으로 답: 차를 가져가도 되는지, 차라면 언제 들어와야 하는지.
- 공연이 끝날 무렵 첫 화면이 **나가기 모드**로 바뀌어, 지금 나갈지 20분 뒤 나갈지 판단하게 한다.
- 처음 오는 사람은 아래로 내려가 하루 미리 보기(3D)와 내 자리에서 보기를 볼 수 있다.
- 고른 공연장·날짜·시각을 기억해 다음에 열면 바로 답이 나온다.

하지 않을 것
- 지하철·버스 혼잡 안내 (데이터 없음). 지하철을 권할 때는 지도 앱 길 찾기 **링크**로 넘긴다(연동 아님).
- 주차장별 안내 (위치 정보가 공공데이터에 없음). 실시간 값은 동2·남2·북2문 주차장 합계로만 쓴다.
- 공원 나들이 모드, 운영자(기관) 화면 개편. 기존 운영자 리포트(`output/report.html`)는 그대로 둔다.
- 홈페이지 자료(공연 일정, 도면, 좌석배치도) 사용. 공연 일정은 홈페이지 링크로만 안내.
- 실시간 값을 10분마다 저장하는 자동 수집 작업 (사용자 승인 전이라 이번 범위에서 제외).

실패로 볼 것 (돌아가도 실패)
- 데이터로 뒷받침되지 않는 문장이 화면에 하나라도 있는 것.
- 처음 보는 사람이 첫 화면에서 3초 안에 "차를 가져갈지"의 답을 못 읽는 것.
- 휴대폰에서 공연 끝난 직후(어두운 공연장, 한 손) 나가기 모드를 읽기 어려운 것.

## 7. 화면 구성 (제안, 빌더가 다듬음)

### 7-1. 첫 화면 = 답 카드
입력: 공연장(5곳), 날짜(오늘부터 2주 정도의 날짜 띠, 평일/주말·공휴일은 자동), 티켓 시작 시각(시간 버튼).
```
 KSPO DOME · 11월 28일 (토) 18:00            [바꾸기]
 ┌─────────────────────────────────────┐
 │ 🚗 차로 간다면 15:00 전에 들어오세요     │
 │    16시부터 주차장이 평소의 2배           │
 │ 🚇 15:00 전에 못 오면 지하철을 권해요     │
 │    [지도 앱에서 길 찾기 ↗]               │
 └─────────────────────────────────────┘
 시간대별 주차장 (막대, 3단계 색)
 ▶ 처음이라면: 공연 날 하루 미리 보기 (3D)
 ▶ 내 자리에서 보기 (KSPO DOME)
```
- 권장 도착 = 시작 1시간 전부터 거꾸로, 지수가 2배 미만인 가장 늦은 시각 (지금 로직 유지). 없으면 "차보다 지하철".
- 비 오는 날 체크 유지 (rain_factor 0.907).
- 당일이면 카드 위에 실시간 줄: "지금 주차장 1,961대 · 이 시각 평소 2,021대와 비슷".

### 7-2. 나가기 모드 (공연 당일, 시작 + 120분 − 15분부터 자동, 손으로도 열 수 있음)
```
 공연 끝났나요?
 지금 나가면    가장 몰리는 10분 (중앙값 113대)
 20분 뒤 나가면 42%로 줄어요            ← 추천
 지금 주차장 3,840대 · 최근 10분 동안 140대 줄었어요
 [ 20분 타이머 시작 ]
```
- 실시간 감소 속도: 1~2분마다 API를 불러 최근 10분 사이 감소량을 계산.
- 타이머: 화면이 열려 있는 동안 20분 뒤 진동·소리·화면 표시. 앱을 닫으면 알림이 없다는 점을 버튼 아래에 적는다.
- 지하철로 온 사람용 줄 없음 (하지 않을 것).

### 7-3. 처음이라면: 공연 날 하루 미리 보기
설계안 v3-1(캔버스 `V3Day`)의 시간 막대: 도착 → 공연 → 끝 → 출차, 단계마다 3D 장면이 바뀜.
KSPO DOME만 "공연" 단계에서 내 자리 시점, 다른 공연장은 기본 시점.

### 7-4. 하루 일정표·캘린더·공유
설계안 v3-2(`V3Plan`). 캘린더 파일(.ics)은 아티팩트 미리보기에서는 다운로드가 막히므로 공개 주소(GitHub Pages)에서만 동작.

## 8. 제약

- 정적 웹 (서버 없음). 공개는 GitHub Pages, 미리보기는 claude.ai 아티팩트.
- 아티팩트 미리보기는 외부 호출이 막혀 실시간 API가 안 됨 → "실시간은 공개 주소에서 보여요" 대체 문구 또는 최근 값 없이 과거 패턴만.
- 3D는 `model-viewer@4.0.0`, Draco 해독기 로컬, 모델 파일 이름 `.glb.wasm`.
- 데이터는 파이프라인(`python run_all.py`)이 만든 JSON만 읽는다. 새 숫자가 필요하면 `src/`에 단계를 추가.
- 화면의 모든 숫자 옆에 출처를 짧게 밝힌다 (? 사용법과 각 카드 하단).

## 10. 검토 후 정한 것 (빌더 검토 질문에 대한 답, [제안]은 설계자 판단)

- [제안] **공연장과 데이터 범위**: 혼잡·출차 데이터는 공원 전체(동2·남2·북2문 주차장) 기준이라 다섯 공연장 모두 같은 주차 답이 나온다.
  화면에 "올림픽공원 주차장은 공연장들이 함께 써요. 공연 날 공원 전체 기준이에요"라고 밝힌다. 공연장 선택은 3D·공연 시간·제목에 쓴다.
  (2024-07 입출차 21.5만 건은 실시간 API 설명의 "입출차 정보 215,528건"과 같은 자료라, 실시간 값과 범위가 같다.)
- [제안] **나가기 모드 근거**: 고정 안내다. 예상 종료(시작 + 120분)를 출차가 몰리기 시작하는 때로 보고
  "지금 나가면 가장 몰리는 때, 20분 뒤면 42%"를 보여 준다. 몰림 모양은 "공연 종료 기준"이 아니라 "가장 몰린 10분 기준"임을 작게 밝힌다.
  절대 대수(113대)는 쓰지 않고 비율만 쓴다.
- [제안] **실시간 값의 역할**: 보여 주기만 하고 권장 답을 바꾸지 않는다. 판정 문장("빠르다/느리다")을 만들지 않는다.
  첫 화면: "지금 주차장 N대". 비교 문구는 2025년 같은 달·같은 요일유형·같은 시각 **공연 날** 중앙값이 있을 때만
  "2025년 이맘때 공연 날 M대"로 나란히 적는다(8~9월은 집계 급감으로 비교 생략). 이 기준값은 파이프라인 단계를 새로 만들어 JSON으로 내보낸다.
  나가기 모드: "지금 주차장 N대 · 최근 10분 동안 K대 줄었어요"만 적는다.
- [제안] **낮 공연**: 출차 몰림 모양은 20:30 이후 저녁 자료라, 예상 종료가 20시 이후인 공연에만 비율을 보여 준다.
  더 이른 공연은 나가기 모드에서 실시간 줄과 "저녁 공연 기록이라 낮 공연엔 비율을 보여 주지 않아요"만 표시.
